# 5060do 수파베이스 신청인원(enrolled) 복원 및 목록 선별 조회

## 목적

1. `public.programs`에 없던 `enrolled` 컬럼을 추가하고 원본 667건의 신청 인원을 재적재해
   실시간 데이터에서도 카드의 `잔여 N석`·진행 막대가 표시되게 한다.
2. 목록 조회에서 상세 본문(`content`)을 빼고 목록 필수 컬럼만 선별 조회(selective select)한다.
3. 대기접수 강좌는 `대기 N명 접수중`으로 표기한다.

## 구현

- 수파베이스 스키마: `ALTER TABLE public.programs ADD COLUMN IF NOT EXISTS enrolled INTEGER DEFAULT 0;`
  (Supabase pooler 직접 연결 psql로 1회 실행. REST API는 DDL을 못 하므로 임시 도구로 처리.)
- `scripts/seed-supabase-programs.mjs`:
  - `toRow`에 `enrolled: formatEnrolled(program.enrolled)` 추가.
  - 시드 전 `assertEnrolledColumn()` 선검사. 컬럼이 없으면 `42703`을 읽어 ALTER 문을 안내하고 중단.
  - 표본 검증 필드에 `enrolled` 추가, 표본 로그에 `enrolled/capacity` 출력, 티켓 ID 갱신.
- `src/lib/programs.ts`:
  - `programListColumns` 상수(`id, title, category, target, capacity, enrolled, fee, edu_period,
    apply_period, location, status, summary, created_at`)로 `select()` 교체(`select('*')` 제거).
  - `SupabaseProgramRow.enrolled` 추가, `parseEnrolled()`로 null/빈값이면 `undefined`.
  - `content`는 선별 조회에서 빠지므로 optional로 변경. `data` 캐스팅은 `unknown` 경유.
- `src/app/page.tsx`:
  - 카드: `seatTotal = max(capacity, enrolled)` 기준 진행 막대(정원 초과 데이터에서도 ARIA 유효).
    대기접수는 `대기 N명 / 정원 M명` + `대기 N명 접수중`.
  - 목록형 표·모바일 행: 대기접수는 `(대기 N명)`, 그 외 `(N석)`.
  - 상세 모달: 대기접수는 `정원 / 대기 N명`.
- `scripts/verify-programs.mjs`:
  - CDP `Network.responseReceived`/`loadingFinished`로 목록 요청의 실제 전송 바이트 수집.
  - 검사 추가: `select=*` 미사용, 전송량 150KB 미만, 실시간 진행바 노출, 잔여석 표기, 대기접수 표기.

## 남은 위험

- 지시서의 `271KB → 160KB(-40%)` 목표는 달성하지 못했다. 원본 `content`가 26건 4.9KB뿐이라
  컬럼을 빼도 줄일 수 있는 상한이 약 5%다. 실제 −40%는 초기 30건 서버 페이징(또는 키 축약)이 필요하다.
- `enrolled`는 2026-11-07 크롤링 스냅샷이다. 원본 사이트 신청 인원이 바뀌면 재크롤링·재시드해야 한다.
- 283건은 `enrolled > capacity`다. 잔여석은 0으로, 막대는 100%로 표시한다.
- 시드 스크립트는 DDL을 하지 않는다. 새 환경에서는 `enrolled` 컬럼이 없으면 안내 문구와 함께 멈춘다.

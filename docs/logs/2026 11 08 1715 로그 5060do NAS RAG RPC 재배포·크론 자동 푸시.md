# 5060do NAS 운영 RAG RPC 실적용·크론 데이터 자동 푸시

## 1. 목표

- NAS 운영 빌드를 `NEXT_PUBLIC_RAG_SOURCE=supabase`로 재배포하고 실운영 챗봇이 `match_documents` RPC를 쓰는지 확인한다.
- 일별 크론이 신규 공고를 갱신하면 `src/data` 2종만 자동 커밋하고 원격에 푸시하도록 만든다.
- 크론 무변경 실행이 워킹트리를 더럽히지 않고 정상 종료하는지 검증한다.

## 2. 구현

- `scripts/deploy-nas.mjs` — 빌드 환경에 `NEXT_PUBLIC_RAG_SOURCE`를 기본 `supabase`로 주입하고 로그에 남긴다. `local`을 주면 번들 모드로 돌아간다.
- `scripts/verify-chatbot-rag.mjs` — `--url=` 옵션 추가. 빌드·로컬 서버 없이 이미 배포된 사이트의 챗봇 답변과 `data-rag-source`, RPC HTTP 상태를 검사한다.
- `scripts/run-daily-cron.sh` — 크롤러 성공 후 데이터 2종 diff가 있을 때만 `git add` → `chore(data): sync incremental jobs (YYYY-MM-DD)` 커밋 → `git push origin master`. GitHub 미러는 `CRON_GITHUB_PUSH=auto|0|1`로 제어하고, 저장된 자격 증명이 없으면 건너뛴다. `GIT_TERMINAL_PROMPT=0`·`GCM_INTERACTIVE=never`로 비대화형 실패를 보장한다.
- 크론 무변경 시 커밋을 만들지 않고 Exit 0, 변경 시 `sync=` 상태를 로그에 남긴다.

## 4. 남은 위험

- NAS에 `crontab` 명령이 없다. Synology 작업 스케줄러나 n8n에 등록해야 한다.
- NAS에 GitHub 자격 증명이 없어 미러 푸시는 워크스테이션에서 `npm run push:github`로 수행해야 한다.
- Windows `core.autocrlf`와 NAS 체크아웃 차이로 크론 첫 실행이 `jobs_all.json`의 CRLF 버전을 커밋했다. 데이터 내용은 같고 이후 크론은 diff가 없으면 커밋하지 않는다.

# 5060do 상태 정렬 status_order 도입 및 칩 카운트 깜빡임 제거

## 목표

1. 전체 목록에서 대기접수 7건이 마지막 페이지로 밀리던 문제를 서버 정렬로 고친다.
2. [더보기] 증분 로드 시 카드가 목록 중간에 끼어들던 덜컥거림을 없앤다.
3. 첫 렌더링에서 로컬 47건 카운트가 667로 바뀌며 깜빡이던 현상을 없앤다.
4. Vercel 정적 배포용 `vercel.json`을 준비한다.

## 구현

- 수파베이스 `public.programs`:
  - `status_order INTEGER DEFAULT 4` 추가, 기존 667건 백필(접수중1·접수예정2·대기접수3·마감4).
  - `CREATE INDEX idx_programs_status_order ON public.programs (status_order, id DESC)`.
  - DDL은 REST로 불가하여 NAS `postgres-common` 컨테이너 psql로 pooler에 접속해 실행.
- `scripts/seed-supabase-programs.mjs`:
  - `STATUS_ORDER` 맵과 `statusOrder()` 추가, `toRow()`가 `status_order` 산출.
  - 시드 선검증·샘플 비교에 `status_order` 포함, 티켓 번호 1405로 갱신.
- `src/lib/programs.ts`:
  - `programListColumns`에 `status_order` 추가, `SupabaseProgramRow` 타입 확장.
  - `fetchProgramPage()` 정렬을 `status_order ASC, id DESC`로 변경.
  - `defaultProgramCounts`(667/7/1/7/652) 추가.
- `src/hooks/usePrograms.ts`:
  - 초기 카운트를 `defaultProgramCounts`로 시작(정적 HTML에 667 고정), 서버 실패 시 로컬 카운트로 복귀.
  - 첫 페이지는 서버 순서 유지, [더보기]는 중복 제거 후 끝에 append(재정렬 제거).
- `vercel.json`: `npm run build` → `out` 정적 출력 설정.
- `scripts/verify-programs.mjs`:
  - 첫 30건 활성 강좌 전건(접수중7·접수예정1·대기접수7) 노출 검증 추가.
  - [더보기] 후 기존 카드 순서 유지 검증 추가.
  - 기존 "접수중 잔여 비율 임박순"을 "상태 그룹 순서·건수 일치"로 대체(서버 정렬 정책 반영).
  - 폴백 카운트 검증을 최대 15초 폴링으로 변경(차단 요청 타임아웃 대응).

## 남은 위험

- Supabase 장애 시 카운트 요청이 타임아웃될 때까지(수 초) 칩은 기본 667, 목록은 로컬 47건으로 서로 다르게 보일 수 있다. 실패가 확정되면 로컬 카운트로 내려간다.

- `vercel.json`은 파일만 준비했다. 실제 Vercel 배포·도메인·basePath(`/5060do`) 동작은 미검증이다.

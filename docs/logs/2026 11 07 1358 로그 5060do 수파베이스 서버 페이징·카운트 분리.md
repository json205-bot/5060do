# 5060do 수파베이스 서버 사이드 페이징·상태별 카운트 분리

## 목적

1. 667건 전체를 한 번에 내려받던 강좌 목록을 초기 30건 범위 조회(`.range`)로 바꿔 초기 전송량을 90% 이상 줄인다.
2. 상태 요약 칩 숫자는 본문 없이 `count: "exact", head: true` 카운트 쿼리 5회로 분리한다.
3. [더보기] 30건 증분 페칭, 총 건수 도달 시 버튼 자동 숨김, 상태 칩 전환 시 1페이지 재조회.
4. 오프라인·수파베이스 실패 시 로컬 `programs.json` 47건 폴백과 시니어 UI(진행 막대·잔여석)는 그대로 유지.

## 구현

- `src/lib/programs.ts`
  - `programPageSize = 30`, `StatusFilter`, `ProgramCounts` 타입 추가.
  - `fetchProgramCounts()`: 전체 + 4상태 = HEAD 카운트 5회. 응답 본문 없이 `count`만 사용.
  - `fetchProgramPage()`: 선별 컬럼 + `order(status.desc)`, `order(created_at.desc)`, `order(id.asc)` + `.range(offset, offset+29)`.
    서버 정렬은 페이징 결정성만 담당하고, 최종 표시 순서는 `comparePrograms()`로 맞춘다.
  - `comparePrograms()`·상태 순위·잔여 비율·접수기간 파싱을 페이지에서 이 파일로 이동.
- `src/hooks/usePrograms.ts`
  - 상태: `probing / ready / failed` + `{filter, items, pages}` 페이지 상태. 이펙트 안 동기 setState 없이 비동기 콜백에서만 갱신.
  - 필터가 바뀌면 파생 렌더에서 이전 필터 목록을 숨기고 1페이지를 새로 조회.
  - `loadMore()`: `loadingMoreRef` 가드, id 중복 제거 후 병합·재정렬, 총 건수 도달 시 중단.
  - 폴백: 카운트 실패 또는 목록 실패 시 카운트를 로컬 47건 기준으로 되돌리고 로컬 30건 페이징.
- `src/app/page.tsx`
  - 칩 카운터를 `counts`(서버 카운트)로, 결과 문구·남은 건수를 `total` 기준으로 변경.
  - [더보기]는 `hasMore`일 때만 노출, 로딩 중 비활성·문구 변경. 목록형 표·모바일 행도 같은 페이징 데이터 사용.
- `scripts/verify-programs.mjs`
  - `Network.requestWillBeSent`로 HTTP 메서드 추적(GET/HEAD/OPTIONS 구분), `Network.getResponseBody`로 원본 JSON 바이트 측정.
  - 초기 목록 gzip·원본 전송량, HEAD 카운트 5건, `offset/limit` 범위 요청, 상태별 칩 7·1·7·652 정확도, 보기 전환 시 페이징 유지 검사 추가.
  - `html { scroll-behavior: smooth }` 때문에 스크린샷 스크롤이 애니메이션 중간에 찍히던 문제 → `behavior: 'instant'`로 수정.

## 남은 위험

- 서버 정렬이 `status.desc`(한글 코드포인트)라 전체 목록 증분 순서는 접수중 → 접수예정 → 마감 → 대기접수다.
  대기접수 7건은 전체 목록에서 마지막 페이지에 나타난다(칩 필터로는 즉시 접근). 상태 순위 컬럼을 두려면 DDL 승인이 필요하다.

- `enrolled`는 2026-11-07 크롤링 스냅샷이며, 원본 사이트 갱신 시 재시드 전까지 값이 어긋난다.

# 5060do 나스 www 정적 배포

## 요약

Next.js 프로토타입을 정적 내보내기(`output: "export"`)로 전환하고 게이트웨이
서브패스 `/5060do`를 붙여 나스 `www` 저장소에 배포했다. 화이트 PC 전원과 무관하게
`http://100.83.116.15:8780/5060do/`에서 상시 접속된다. 실서버 HTTP 200,
정적 리소스 404 0건, 390px 모바일 E2E 전 흐름 PASS.

## 실행·검증

1. `npm run typecheck` → Exit 0
2. `npm run lint` → Exit 0
3. `npm run build` → Exit 0, `out/` 25개 파일 생성
4. `deploy_www.sh /volume1/workspace/dev/5060do/out 5060do` → 25개 파일 배포
5. `www_index.sh` → 37개 사이트 목록 갱신, `5060do static` 등록
6. 실서버 `GET /5060do/` → 200 (32,420 bytes)
7. HTML·CSS 참조 정적 리소스 9건 → 전부 200, 404 0건
8. Chrome CDP E2E (`BASE_URL=http://100.83.116.15:8780/5060do/`)
   - 390/768/1280px 열 수 1/2/3, 가로 스크롤 없음, 글자 18px, 48px 미만 터치 0건
   - 카드→모달→신청 폼→가상 결제→완료 화면→모집 마감 비활성 전부 통과
   - 콘솔 오류 0건(정상 로그 1건만)

## 남은 위험

- 정적 배포라 서버 API·DB 연동은 없다(프로토타입 범위).
- 나스 `www`는 공개 게이트웨이이므로 접근 통제는 테일스케일 네트워크에 의존한다.
- `out/`은 git 추적 대상이 아니며, 재배포는 빌드 후 `deploy_www.sh`를 다시 실행해야 한다.

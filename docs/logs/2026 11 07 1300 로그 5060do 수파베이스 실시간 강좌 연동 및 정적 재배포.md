# 5060do 메인 화면 수파베이스 실시간 강좌 연동 및 정적 재배포

## 목적

`public.programs` 667건을 메인 화면이 실시간 조회하도록 바꾸고, 정적 내보내기(`output: "export"`)를
유지한 채 네트워크·RLS 장애 시 로컬 데이터로 폴백한다. 667건 렌더 부담은 30건 단위 점진 로딩으로 줄인다.

## 구현

- `src/lib/supabase.ts`: publishable 키 기반 브라우저 클라이언트 1회 생성. 키 누락 시 경고 후 `null` 반환.
- `src/lib/programs.ts`: `programs` 테이블 행 → 화면 `Program` 매핑. `capacity`(`20명`)·`fee`(`무료`/`10,000원`)를
  숫자로 파싱, `status`는 4종 외 값이면 `마감`. 테이블에 `enrolled`가 없어 신청 인원은 미표시 처리.
- `src/hooks/usePrograms.ts`: 로컬 `programs.json`(47건)으로 즉시 렌더 → 마운트 후
  `select('*').order('created_at', { ascending: false })` 결과로 교체. 실패 시 로컬 유지.
- `src/app/page.tsx`: 강좌 데이터를 상태로 전환, 4대 칩 카운트는 전체 기준 `useMemo` 집계,
  `PAGE_SIZE=30` 점진 로딩(56px `더 많은 강좌 보기 (+30개)` 버튼), 칩 변경 시 30건으로 리셋.
  카드·목록·모바일 목록 모두 동일 슬라이스 사용. 실시간 여부는 `#programs[data-programs-source]`로 노출.
- `scripts/verify-programs.mjs`: 점진 로딩 대응(초기 30건 → +30 확인 후 전건 확장), 실시간 수신 대기,
  수파베이스 차단 폴백 검증, 더보기 버튼 스크린샷 추가.

## 남은 위험

- `programs` 테이블에 `enrolled`·`source_url`이 없어 실시간 데이터에서는 신청 인원·잔여석과 원문 링크가 표시되지 않는다.
- 전건 `created_at`이 시드 시각으로 동일해 `order('created_at')` 정렬은 사실상 무순서다. 화면 정렬은 클라이언트가 담당한다.
- `select('*')`는 `content` 포함 271KB(비압축)를 받는다. 트래픽이 커지면 컬럼 선택으로 줄여야 한다.
- 상태값은 시드 시점(2026-11-07) 스냅샷이다. 시간이 지나면 재시드가 필요하다.

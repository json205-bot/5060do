# 5060do 뷰포트 테스터 postMessage 동기화 리스너 연동

## 1. 목표

- 고지기 반응형 멀티 뷰포트 테스터(선행 티켓 GOJIGI-20261110-1330)가 5060do를 iframe으로 로드할 때, 교차 출처에서도 8개 프레임의 스크롤 진행률과 페이지 경로가 동기화되게 한다.
- 일반 사용자가 iframe 없이 접속할 때는 이벤트 리스너와 연산이 0이 되도록 한다.

## 2. 구현

- `src/components/ViewportSyncHelper.tsx` 신규 생성.
  - `window.self !== window.top`일 때만 이펙트를 활성화한다. iframe 밖에서는 DOM·리스너·postMessage가 모두 없다.
  - 스크롤 송신: `scroll` 이벤트를 `requestAnimationFrame`으로 묶어 `scrollTop / (scrollHeight - clientHeight)` 진행률을 `frame:scroll`로 부모에 보낸다.
  - 스크롤 수신: `source: 'gojigi-viewport-sync'`, `type: 'parent:scroll'`만, `event.source === window.parent`일 때만 받아 `behavior: 'instant'`로 반영한다. 사이트 전역 `scroll-behavior: smooth`가 동기화 스크롤을 애니메이션으로 만들어 다시 송신하는 루프를 막는다.
  - 루프 방지: 수신 반영 직후 300ms `suppressUntil`과 `lastSentRatio`로 재송신을 차단한다.
  - 준비·경로 알림: 최초 마운트와 load 시 `frame:ready`(href)를 보낸다. `pushState`/`replaceState` 래핑, `popstate`, `hashchange`, Next.js `usePathname` 변경 시 `frame:ready`와 `frame:navigate`(url)를 함께 보낸다.
    - `frame:ready`는 1430 지시서 규격이고, `frame:navigate`는 선행 1330 엔진이 교차 출처에서 실제로 수신하는 타입이다. 둘을 함께 보내 두 티켓을 모두 만족시킨다.
- `src/app/layout.tsx` 루트 레이아웃 body에 `<ViewportSyncHelper />`를 마운트했다.
- `scripts/verify-viewport-sync.mjs` 신규 추가.
  - 5060do 정적 산출물(3112)과 하네스(3113)를 다른 포트로 띄워 실제 교차 출처 iframe을 만든다.
  - 송신·수신·루프 방지·pushState/popstate/문서 이동·비 iframe 비활성 11개 항목을 CDP로 검증한다.

## 5. 남은 위험

- `frame:ready`는 선행 1330 엔진이 아직 해석하지 않는다. 경로 동기화는 `frame:navigate`가 담당하므로 동작에는 문제가 없지만, 1330 엔진이 `frame:ready`를 핸드셰이크로 쓰도록 바뀌면 양쪽 합의가 필요하다.
- 스크롤은 문서 루트 기준이다. 5060do는 내부 스크롤 컨테이너를 쓰지 않아 현재는 문제가 없지만, 추후 모달·패널 내부 스크롤까지 동기화하려면 컨테이너 지정이 필요하다.
- iframe 안에서 외부 사이트로 이동하면 5060do 헬퍼가 사라지므로 그 이후 동기화는 대상 사이트 책임이다.
- `history.pushState` 래핑은 iframe 안에서만 설치·해제된다. 같은 페이지에 다른 코드가 pushState를 재정의하면 마지막 정의가 이긴다.
